# ADR 0009 — Kenney FPS Pack import deferred to post-v0.1

Date: 2026-05-30  
Status: Accepted  
Deciders: nvrohan (standing approval — ADR 0007), kurukshetra-autonomous-build cron

## Context

D4.10 in STATUS.md asks for "Kenney FPS Pack assets imported + ATTRIBUTIONS
updated". The original intent was to drop in Kenney's CC0 weapon models,
character meshes, and prototype textures so the v0.1 playtest doesn't
look like a programmer-art capsule fight.

The autonomous build worker tried to fetch Kenney's bundles directly:

- `https://kenney.nl/media/pages/assets/blaster-kit/.../kenney_blaster-kit.zip`
- `https://kenney.nl/media/pages/assets/prototype-textures/.../kenney_prototype-textures.zip`

Both responses are HTML — Kenney's CDN serves the asset detail page when
the request lacks a fresh download token. The "real" zip is fetched via a
session-bound dynamic URL generated by JavaScript on the page. That flow
needs a real browser session (or an authenticated mirror), neither of
which the unattended cron job has.

Mirrors checked:

- `nidorx/kenney-game-assets` GitHub releases — repo exists, releases page 404s.
- `opengameart.org` direct asset URLs — return HTML, same problem.

## Decision

**Defer D4.10 until a human can pull the Kenney bundles via browser and
drop them into `assets/`.** The MVP smoke test passes without them: every
gameplay system (movement, weapons, armor, knockdown/revive, loot,
zone, kill feed) runs on placeholder geometry (capsules + colored
boxes) and validates real multiplayer behaviour. Asset polish is
strictly cosmetic and orthogonal to "is the game playable".

This ADR documents D4.10 as **🚧 awaiting-manual** in STATUS.md so the
deliverable count is honest.

## Consequences

- D4 ✅ promotion to "local-complete" requires only 4.0–4.9 + 4.11. We
  treat 4.10 as a polish item in v0.1.1, not an MVP blocker.
- The smoke-test gate (4.11) runs on the placeholder build — same as
  every cron tick so far. No regression risk from the deferral.
- When Rohan has time to download the Kenney FPS Pack
  (`https://kenney.nl/assets/blaster-kit` — CC0) and the Kenney
  Prototype Textures (`https://kenney.nl/assets/prototype-textures` —
  CC0), the import is straightforward:
  1. Drop unzipped folders into `assets/kenney/`.
  2. Update `ATTRIBUTIONS.md` per the existing format.
  3. Replace `CapsuleMesh` in `scenes/player.tscn` with
     `ResourceLoader.load("res://assets/kenney/character_male/character.glb")`.
  4. Replace `BoxMesh` cubes in `scenes/match.tscn` with prototype
     texture-mapped variants for visual interest.
- License is unchanged: CC0 keeps the repo MIT-clean. The hard rule in
  ATTRIBUTIONS.md still holds — every imported file gets a row.

## Alternatives considered

1. **Hand-craft procedural meshes in code.** Possible but expensive —
   any time spent making art is time not spent on testable game systems.
   The MVP doesn't need pretty geometry; it needs *correct* geometry,
   which the placeholders already are.
2. **Use a different CC0 source (ambientCG, OpenGameArt).** Same fetch
   problem — these sites also serve through dynamic CDN tokens or
   require user-agent-aware scraping that's out of scope for the cron.
3. **Pin a specific GitHub mirror.** None of the inspected mirrors are
   stable enough to depend on; a 404 mid-build would break CI.

The "ADR + skip and continue" path is the right one per
[CRONTASK rule 7](../../STATUS.md#how-the-cron-continuation-works) and
ADR 0007 standing approval.
